# Security Policy

English | [日本語](#日本語)

## Reporting a Vulnerability

If you discover a security vulnerability in commiter-cli, please do not report it through a public GitHub Issue or Discussion.

Please report the vulnerability privately using GitHub's **Private Vulnerability Reporting** feature.

When reporting a vulnerability, please include as much of the following information as possible:

- A description of the vulnerability
- Steps to reproduce the issue
- The affected version or commit, if known
- The potential security impact
- Any suggested mitigation or fix, if available

We will review the report and respond as soon as reasonably possible.

Please avoid publicly disclosing the vulnerability until it has been investigated and, where necessary, a fix has been released.

# 日本語

## 脆弱性の報告方法

commiter-cli におけるセキュリティ上の脆弱性を見つけた場合は、公開の GitHub Issue や Discussion には投稿せず、GitHub の Private Vulnerability Reporting 機能を利用して非公開でご報告ください。

報告の際は、わかる範囲で構いませんので以下の情報をご提供いただけますと幸いです。
- 概要: どのような脆弱性か
- 再現手順: 問題を再現するための具体的な手順
- 影響範囲: 影響を受けるバージョンやコミットハッシュ
- セキュリティ上の影響: 想定されるリスクや被害
- 修正案・回避策: 提案可能な修正方法や一時的な回避策（任意）

ご報告いただいた内容は速やかに確認し、適切な対応を行います。
なお、調査が完了してパッチ(修正版)が公開されるまでは、対象の脆弱性に関する情報を公表しないようご協力をお願いいたします。
